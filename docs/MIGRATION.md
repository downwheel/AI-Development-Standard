# 이전 개발 표준에서 전환

최초 사용자에게는 이 문서가 필요 없다. `development-workflow`, 이 저장소의 이전 `dev-*` 스킬, 구 공통 하네스 지침 또는 `team_harness` MCP가 연결된 사용자에게만 적용한다. 현재 27개 한국어 스킬을 이미 사용하고 있다면 일반 업데이트 절차를 사용한다.

## 전환 범위

전환은 Codex의 구 팀 표준 연결만 해제하고 현재 스킬을 설치하는 작업이다. 제품 소스, 기존 Workspace·프로젝트 연결, 개인 작업 기록과 고정 실행본, 외부 MCP·플러그인, Claude Code는 보존한다. 오래된 제품 프로젝트의 AGENTS.md는 첫 설치에서 일괄 수정하지 않는다. 해당 프로젝트를 시작할 때 기존 표준을 참조하는 부분만 현재 방식으로 연결한다.

설치 도구는 구 표준을 발견하면 쓰기 전에 중단한다. AI는 아래 절차로 전환을 진행할 수 있다. 사용자가 이 START-HERE에 따른 전환 설치를 요청했고 확인된 대상이 그 범위와 일치하면 같은 작업을 단계마다 다시 승인받지 않는다. 소유권이나 충돌이 불명확할 때 해당 부분만 질문한다.

## AI 실행 절차

1. 실제 Codex 설정 경로를 확정한다. 구 스킬의 `runtime.json`, 개인 state의 `installation.json` 및 그 파일이 가리키는 receipt를 확인해 구 표준의 설치 위치와 파일 소유권을 식별한다. 다른 사용자의 경로를 복사하거나 `dev-*` 전체를 이름만 보고 삭제하지 않는다. 현재 노출된 구 도구를 실행해 새 작업 기록을 만들 필요는 없다.
2. 개인 백업 폴더를 배포 저장소·제품·Skill 검색 경로 밖에 만든다. 구 스킬 디렉터리, Codex `AGENTS.md`와 `config.toml`, 소유권 receipt를 복사하고 SHA-256으로 원본과 일치를 확인한다. 백업에 자격 증명이 포함될 수 있으므로 개인 영역에만 보관하고 Git 또는 배포 ZIP에 넣지 않는다. 구 state 자체는 옮기거나 삭제하지 않는다.
3. 소유권이 확인된 구 스킬 디렉터리만 백업으로 이동해 Codex 검색 대상에서 제외한다. 로컬 수정과 추가 파일도 함께 보존하고 경로를 보고한다. 링크·reparse 경로, 다른 스킬과 섞인 디렉터리 또는 소유권 자료 누락은 자동 정리하지 않고 충돌로 남긴다.
4. `AGENTS.md`에서 정확히 짝이 맞는 `team-development-standard:managed:start/end` 또는 `development-workflow:managed:start/end` 관리 구간만 제거한다. 나머지 바이트는 보존한다. 관리 구간의 개수나 경계가 모호하면 자동으로 잘라내지 않는다.
5. `config.toml`에서는 구 표준임이 확인된 `mcp_servers.team_harness`와 `mcp_servers.development_workflow` 테이블 및 해당 하위 테이블만 제거한다. 현재 연결된 Context7, Figma, 브라우저, DB 등 외부 항목은 그대로 둔다. TOML 파서를 이용해 수정 전후의 의미를 비교하며 제거 대상 외의 설정이 동일함을 검증한다. 사용 가능한 안전한 편집 방법이 없으면 연결 해제만 미완료로 보고한다. 비밀 값은 출력하지 않는다.
6. 백업과 외부 설정 보존을 확인한 뒤 START-HERE의 설치 미리보기 → 적용 → 검증을 이어간다. 구 표준 `settings.json`의 `workspaces_root`가 확인되면 설치 미리보기와 적용에 같은 `--workspace-root` 절대 경로를 명시한다. 설치기는 구 state 설정을 자동 탐색하지 않는다. 원래 사용하던 Claude 설정은 이번 전환 범위에 포함하지 않는다.

## 충돌 및 되돌리기

- 현재 팀 스킬의 로컬 변경 때문에 설치가 차단되면 내용을 먼저 비교한다. 유지할 수정은 팀 원본에 통합하거나 개인 스킬로 분리할 범위를 정한 후 다시 설치한다. receipt나 해시를 임의 수정해 덮어쓰기를 강제하지 않는다.
- 일반 업데이트의 기존 파일은 `<codex-home>/team-skills-backups/<시각>/`에 남는다. `team-skills-receipt.json`의 `last_backup`으로 위치를 확인한다.
- 복원이 필요하면 먼저 현재 설치와 백업의 차이를 확인한다. 복원 대상 파일이 그 뒤에 수정되지 않았는지 확인하고, 해당 설치의 파일과 관리 구간만 복원한다. 개인 config 전체나 AGENTS.md 전체를 오래된 사본으로 덮어쓰지 않는다.
- 구 표준으로의 복귀는 현재 팀 스킬을 비활성화하고 구 연결을 복원하는 별도 요청이다. 두 워크플로를 동시에 활성화하지 않는다. 이전 저장소 내용을 다시 사용할 때는 기존 Git 이력 또는 개인 백업을 이용하고 현재 배포 원본과 섞지 않는다.

전환 결과에는 백업 경로, 해제한 구 표준 항목, 보존한 Workspace와 외부 연결, 현재 설치 검증 및 미완료 항목만 간단히 남긴다. 새 승인 원장이나 실행 상태 엔진을 만들지 않는다.

## Claude Code 적용

위 Codex 전환 절차는 Codex를 대상으로 한 기존 배포의 전환 설명이다. Claude Code에도 구 팀 표준이 있으면 같은 소유권 확인·백업·보존 원칙을 적용하되 실제 Claude 설정 위치를 사용한다. `CLAUDE.md`의 구 관리 블록, 사용자 `.claude.json`의 구 팀 MCP, 프로젝트별 구 `.mcp.json` 연결을 확인한다. 이름만 보고 개인 도구를 삭제하지 않는다. 확인한 구 표준 연결만 백업 후 해제하고 외부 Figma·Context7 등은 유지한다.

신규 사용자는 전환 없이 START-HERE-CLAUDE.md를 실행한다. 현재 팀 스킬 사용자는 같은 시작 문서로 일반 업데이트한다. 기본 외부 도구의 설정 백업은 `<profile>/team-tools-backups`에 있으며 팀 스킬 백업과 구분한다. 두 호스트를 사용하는 경우 어느 쪽을 복원하는지 먼저 확인한다.
