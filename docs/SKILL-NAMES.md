# 스킬 호출 이름

3.2.0부터 Codex와 Claude Code의 27개 팀 스킬 이름·폴더·표시 이름을 짧은 영문으로 통일한다. 설명과 작업 절차는 한국어 설명을 포함한 기존 내용을 유지한다. Codex는 `$hi`, Claude Code는 `/hi`로 시작한다.

| 이전 이름 | 새 이름 | 한국어 설명 |
|---|---|---|
| 작업길잡이 | `hi` | 요청과 진행 상태를 파악해 적합한 개발 절차와 스킬로 연결합니다. |
| 오류진단 | `diagnose` | 오류를 재현하고 원인을 검증해 수정과 회귀 검사까지 진행합니다. |
| 요구정리 | `clarify` | 요구사항을 질문으로 구체화하고 확정된 용어와 중요 결정을 기록합니다. |
| 요청분류 | `triage` | 접수 요청의 중복과 재현 여부를 확인하고 처리 상태와 작업 설명을 정리합니다. |
| 구조개선 | `refactor` | 코드 구조의 문제와 개선 후보를 조사하고 전후 비교 보고서를 만듭니다. |
| 프로젝트설정 | `setup` | 프로젝트의 이슈 관리와 문서 경로를 설정하고 하네스에 연결합니다. |
| 테스트주도 | `tdd` | 실패 테스트와 최소 구현을 반복해 공개 인터페이스의 동작을 검증합니다. |
| 설계작성 | `design` | 화면과 처리, 데이터, 검증 설계를 묶어 제시하고 사용자 승인을 받습니다. |
| 작업분할 | `tickets` | 설계를 검증 가능한 구현 작업으로 나누고 완료 조건과 의존 관계를 정리합니다. |
| 방향탐색 | `explore` | 크고 불확실한 작업의 결정 지도를 만들고 조사와 질문으로 방향을 정합니다. |
| 구현 | `implement` | 승인된 작업을 구현하고 관련 검사와 코드 검토까지 완료합니다. |
| 통합구현 | `integrate` | 여러 구현 작업의 의존 관계를 관리하고 통합과 기능 및 화면 검증을 수행합니다. |
| 시제품 | `prototype` | 상태와 로직을 조작하거나 화면 대안을 비교하는 실험용 시제품을 만듭니다. |
| 자료조사 | `research` | 공식 문서와 소스를 조사하고 출처가 있는 결과를 외부 작업 공간에 기록합니다. |
| 도메인정리 | `domain` | 업무 용어를 명확히 하고 코드와 대조해 용어집과 중요한 설계 결정을 정리합니다. |
| 모듈설계 | `modules` | 모듈의 책임과 인터페이스를 설계하고 교체 지점과 테스트 경계를 검토합니다. |
| 코드검토 | `code-review` | 코드 변경을 저장소 규칙과 요구사항 충족의 두 관점에서 검토합니다. |
| 변경요약 | `pr-summary` | 변경 구조와 검증 증거, 영향 범위를 정리해 검토할 변경 제안 본문을 작성합니다. |
| 개발회고 | `retro` | 개발 기록을 분석해 반복 실수와 병목, 스킬 및 하네스의 개선점을 찾습니다. |
| 수동안내 | `manual` | 사람이 직접 해야 하는 인증과 설정 작업을 단계별 실행 안내로 만듭니다. |
| 구상검토 | `discuss` | 문서 축적 없이 구상의 가정과 결정을 질문으로 검토하고 구체화합니다. |
| 심층질문 | `interview` | 계획과 결정의 의존 관계를 따져 필요한 질문과 권장안을 묶어 제시합니다. |
| 인수인계 | `handoff` | 결정과 진행 상태, 남은 작업과 참고 경로를 다음 담당자에게 전달합니다. |
| 학습 | `learn` | 학습 목적과 기록에 맞춰 짧은 수업과 연습, 참고 자료를 만듭니다. |
| 질문서 | `questions` | 다른 담당자에게 확인할 사실과 결정을 회의나 비동기 응답용 질문서로 만듭니다. |
| 쉬운설명 | `explain` | 직전 설명에 필요한 맥락을 보태고 익숙한 업무 용어로 쉽게 다시 설명합니다. |
| 지침작성 | `instruct` | 스킬과 하네스의 호출 조건과 절차를 명확히 하고 중복되거나 과한 지침을 줄입니다. |

## 업데이트

Git Pull 후 사용하는 호스트의 START-HERE 문서를 다시 실행한다. 설치 영수증이 소유하고 원본 해시와 일치하는 한글 스킬은 백업 폴더로 이동하고 영문 스킬을 설치한다. 개인 수정이나 알 수 없는 추가 파일은 보존하며 충돌을 보고한다. 정상 적용 후 활성 스킬 폴더에는 한글 호출용 사본을 남기지 않는다.

스킬 이름이 바뀌므로 기존 프롬프트와 프로젝트 문서에 직접 적은 호출은 위 표에 맞춰 바꾼다. 설치기는 팀 관리 블록과 설치 사본을 갱신하며 모든 제품 저장소·개인 문서를 일괄 편집하지 않는다. 새 세션에서 영문 이름을 사용한다. 16개 직접 호출형·11개 자동 선택 가능 정책, 외부 Workspace, MCP·플러그인 연결은 유지한다.
