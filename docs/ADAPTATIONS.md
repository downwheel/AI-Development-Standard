# 공통 개발 기준과 호스트 적용

현재 배포본은 27개 스킬의 실제 호출 이름, 폴더 이름, 표시 이름을 짧은 영문으로 통일하고 설명은 한국어로 유지한다. Skill 본문의 작업 절차는 유지하며 내부 참조도 같은 이름을 사용한다. 기본 진입점은 `hi`다.

| 범위 | 기준 |
|---|---|
| 호출 | Codex는 `$skill-name` 또는 선택 UI, Claude Code는 `/skill-name`으로 시작하고 필요한 후속 스킬은 설치된 파일을 읽어 적용한다. |
| 호출 정책 | 직접 호출형 16개, 자동 선택 가능 11개의 구분을 유지한다. |
| 프로젝트 설정 | Codex는 AGENTS.md, Claude Code는 CLAUDE.md를 사용한다. 한 호스트의 설치가 다른 호스트의 지침을 수정하지 않는다. |
| 설계 | 새 기능과 주요 변경은 필요한 화면, 처리, 데이터, 검증 설계를 묶어 제시한다. |
| 승인 | 요구 답변과 실제 설계 승인을 구분한다. 기존 승인을 재사용하고 실질적으로 달라진 부분만 검토한다. |
| 질문 | 코드에서 확인할 사실은 조사하고, 합의한 결정과 기계적인 작업 분할을 반복 질문하지 않는다. |
| 도구 | 필요한 기능과 프로젝트 적합성으로 선택하고 실제 기여, 대체 사유와 미검증 범위를 보고한다. |
| 화면 | 기존 화면, 공통 컴포넌트와 테마를 기준으로 하며 Figma 또는 편집 가능한 로컬 시안을 사용한다. |
| 검사 | 지정 환경을 재사용하고 실제 변경 반영을 확인한다. 관련 미커밋 및 신규 파일도 리뷰한다. |
| 저장 | 신규 AI 테스트와 중간 산출물은 외부 Workspace에 둔다. 기존 제품 문서는 보존한다. |
| Windows | 실행 도구와 셸을 확인한다. Bash가 없으면 검토 가능한 PowerShell 절차를 제시한다. |
| 외부 작업 | 구현만으로 commit, push, 외부 게시, 배포, 운영 데이터 변경을 승인한 것으로 간주하지 않는다. |
| 라이선스 | 원본의 저작권과 사용 허가 고지를 저장소 및 개별 스킬의 LICENSE에 보존한다. |

개인 경로는 team-skills.json에서 확인한다. 관리 지침은 스킬의 일반적인 상대 산출물 예시보다 프로젝트의 실제 Workspace 연결을 우선한다. 별도 승인 원장이나 자체 실행 엔진을 추가하지 않는다.

설계와 도구 선택의 상세 기준은 `design/references/`에 모으고 구현과 리뷰 진입점이 참조한다. 모든 도구 호출, 전수 회귀 검사, 반복 URL 질문을 요구하지 않는다.

이름 변경의 검증 범위는 메타데이터, 내부 참조, 배포 파일, 격리 설치와 재설치, 현재 Codex와 Claude Code의 실제 인식이다. 27개 스킬의 전체 업무 수행을 검증한 것은 아니다. 이름은 호스트 간 호환성을 위해 ASCII 영문 소문자·숫자·하이픈만 허용한다.

Claude Code는 Codex의 `agents/openai.yaml` 대신 SKILL.md의 `disable-model-invocation`을 사용한다. 직접 호출형 16개는 true, 자동 선택 가능한 11개는 false다. 사용자 요청 범위에서 다른 스킬 문서를 읽어 절차를 적용할 수 있으나, 직접 호출 전용 스킬을 Skill 도구가 임의 호출할 수 있다고 가정하지 않는다. 설치 시 `allowed-tools` 등 광범위한 권한을 부여하지 않는다.

기본 외부 도구는 [INTEGRATIONS.md](INTEGRATIONS.md)를 따른다. 도구가 구성되어 있다는 이유로 매번 모두 호출하지 않는다. 기존 디자인과 검증 환경에 맞는 기능을 선택하고 계정 없는 로컬 시안을 지원한다.
