# 계정·원격 연결 후속 작업

공통 표준과 개인 실행 설정 구성만으로 외부 계정 로그인이 완료되지는 않는다. 현재 작업에 필요한 서비스만 각 사용자 권한으로 연결한다. 이 문서에는 실제 토큰·암호·개인 경로를 저장하지 않는다. 공통 Git 주소와 Sourcetree 절차는 [Git 배포 가이드](git-distribution.md)에서 확인한다.

| 후속 항목 | 사용자가 정할 것/할 일 | 완료 확인 |
|---|---|---|
| Team 공통 Git 접근 | 소유자가 팀원별 GitHub 계정을 확인하여 초대하고, 팀원은 수락 후 자신의 계정으로 clone | 실제 clone과 부여 권한을 확인하고 공통 표준만 내려받는지 확인 |
| Figma | 사용할 개인 계정과 대상 팀/파일 권한 연결 | 대상 읽기와 필요한 native 편집 능력을 각각 확인 |
| Context7 | 현재 호스트 연결, 필요 시 개인 API key/OAuth | 특정 library/version의 문서 조회와 공식 원문 확인 |
| 프로젝트 DB MCP | 정확한 서버 제품·DB 범위·읽기 계정·네트워크/TLS·쿼리 한도 | 허용 metadata 최소 조회와 오류 구분 |
| 브라우저 MCP | 필요 시 Microsoft Playwright MCP와 검사 전용 profile | 허용 테스트 URL의 실제 조작/관찰 |
| Claude Code | 사용하려면 CLI 설치·인증 후 새 세션 | native Skill discovery와 team_harness STDIO 실행 확인 |

설치기에는 Team Git 원격 생성·연결·commit/push·외부 로그인 동작을 넣지 않는다. 기존 MCP는 보존 대상이며 새 표준이 다른 서버의 계정을 대체하지 않는다. 구 workflow와 v2가 동시에 새 기록을 만들지 않게 관리한다.

공통 저장소의 소유자 토큰이나 로그인 정보를 팀원에게 배포하지 않는다. 비공개 저장소의 주소를 전달하는 것만으로 팀원에게 접근 권한이 생기지 않는다. 기본 collaborator 초대는 읽기 전용 배포 권한으로 간주하지 않으며 실제 부여 권한을 확인한다. 상세 근거와 운영 방식은 [Git 배포 가이드](git-distribution.md#접근-권한과-계정)에 있다.

Codex는 설정 반영 후 재시작/새 세션에서 도구 노출을 확인한다. Claude용 Skill/MCP 설정 파일이 준비돼 있어도 Claude CLI가 없는 호스트에서는 실제 로딩을 미검증으로 표시한다.

공급자별 단계와 공식 링크는 [외부 MCP 연결 가이드](../integrations/connection-guide.md)에 있다. 계정 연결의 성공, 특정 대상 읽기, 쓰기 가능, 제품 기능 검증을 따로 보고한다. 쓰기 테스트가 필요하면 허용된 대상과 구체적인 범위에서 한다.

개인 history Git은 기본 remote 없음으로 운영한다. 향후 백업을 원격에 둘 경우에는 소스 사본·개인 설계·로그가 포함되는 별도 저장 영역임을 고려하여 사용자가 백업 대상·암호화·접근권한·보존 기간을 정해야 한다. Team 공통 Git을 개인 이력 백업 경로로 사용하지 않는다.
