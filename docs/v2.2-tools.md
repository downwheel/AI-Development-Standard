# 2.2 외부 MCP 활용 정책과 실행 계약

2.2.0은 2.1의 환경·파일/DB 범위·승인·개인 이력을 유지하면서 외부 도구의 사용 계획, 실제 관찰, 필수 실행 증거를 연결한다. core `contract_version`은 `2.1`, 새 run의 `tool_policy_version`은 `"1"`이다. 기존 run의 고정 release와 정책을 자동 변경하지 않는다. 실제 operation은 `describe`, payload 상세는 같은 release의 `contracts/artifact-payloads.json`과 typed 도구 결과의 `contracts/tool-policy.json`이 권위다.

## 언제 어떤 MCP를 사용하는가

| 단계 | 기본 도구와 구체적인 작업 | 다음 단계로 넘기는 근거 |
|---|---|---|
| 조사 | 프로젝트별 DB MCP/내부 SQL adapter로 metadata·제한 조회, 기존 화면 브라우저 관찰, 허용된 Figma 기존 파일 읽기 | 실제 소스·버전·대상·도구 준비도, 조사 범위와 미확인 |
| 시스템 설계 | Context7로 버전 의존 기술 선택 확인, OpenAI 관련 선택은 OpenAI Docs 우선 | 기술 선택 근거와 네 capability의 tool_plan → Gate A |
| UI 단위 설계 | Figma 기존 component/token 조사, 필요한 native 화면·상태 작성, 구조·screenshot 재조회 | file/node 참조와 실제 관찰 또는 승인된 로컬 대안 |
| API/데이터/통합 단위 설계 | Context7로 SDK/API·설정·드라이버 계약 확인, 공식 원문·설치 타입 대조, 실제 DB catalog 확인 | 정확한 API/DB 계약과 unit.tool_observations |
| 테스트 설계 | 브라우저로 과업 탐색, Context7로 테스트 도구의 버전별 fixture·격리·대기 동작 확인 | 실제 브라우저·DB 재조회가 필요한 tool_checks와 지속 회귀 runner → Gate B |
| 구현 | 승인한 Figma/로컬 설계 재확인, 새 버전 쟁점만 공식 문서 재조회, 승인한 DB 계획 적용 | source/DB receipt, 변경된 사실과 설계 영향 |
| 검증 | 실제 브라우저 조작·관찰, DB 독립 재조회, 저장된 테스트 runner 실행 | 현재 build/run에 묶인 필수 JSON 증거와 case 결과 |

MCP 호출 횟수가 성과 지표는 아니다. 같은 설치 버전·범위의 유효한 근거는 재사용한다. 단순 문구 수정, 외부 버전 계약이 없는 자체 계산 로직, UI/DB 없는 제품에 모든 서비스를 억지로 사용하지 않는다. 도구가 안 연결되어 있다는 사실은 제품에 해당 기능이 없다는 이유가 아니다.

## 기본 정책과 대체 조건

**Figma:** UI의 기본은 `preferred`다. 현재 호스트의 실제 도구로 Figma를 먼저 시도한다. 편집 가능한 native 설계가 명시 요구이면 `required`, 사용자가 처음부터 로컬 설계를 명시 선택하면 `local_only`다. local_only의 근거를 AI가 만들어서는 안 된다.

- required: 실제 native file/node와 구조·screenshot 확인이 필요하다. 권한·쿼터·편집 도구 부재이면 해당 완료를 보류한다. 독립적인 로컬 초안은 제공할 수 있다.
- preferred: 실제 Figma 차단을 기록하고, Gate A에서 승인한 HTML/SVG 배치안+화면 계약으로 대체할 수 있다. 막히지 않았는데 편의상 Figma를 생략하지 않는다.
- local_only: 실제 사용자 선택 출처와 구체적인 로컬 배치안/계약을 기록한다.
- not_applicable: UI가 없다는 등 제품 범위 이유가 필요하다.

Figma의 호출 rate limit, 계정 사용 한도, 저장 공간/파일 생성 제한, 대상 파일의 읽기/편집 권한을 구분한다. 연결 상태로 잔여 용량을 추정하지 않는다. 자동 계정 변경·결제·권한 확대·중복 연결을 해결책으로 실행하지 않는다. [Figma 상세](../integrations/figma.md)

**Context7:** 새 라이브러리 선택, 버전 의존 SDK/API·설정·드라이버·테스트 도구 결정은 `library_docs: required`다. 실제 package/lockfile 버전과 질문을 정하고 library 식별→문서 조회→공식 원문·설치 타입/SDK 대조→설계 결정 기록으로 연결한다. 이미 확인한 ID는 재사용한다. 설치 전 기술 선택이면 설치 미확인과 확인한 공식 API 계약의 범위를 명시하고 구현 전 실제 타입을 다시 확인한다. 연결 불가·library/버전 부재이면 실제 원인과 공식 문서 대체를 남긴다. [Context7 상세](../integrations/context7.md)

**OpenAI Docs:** OpenAI 제품/API·Codex 관련 결정은 Context7보다 먼저 사용한다. 해당 범위와 이유, 공식 OpenAI 출처를 기록한다. API 모델 호출이나 유료 시험이 자동으로 허용되는 것은 아니다. [OpenAI Docs 상세](../integrations/openai-docs.md)

**브라우저:** UI 단위에는 `browser: required`가 함께 있어야 한다. Microsoft Playwright MCP 또는 해당 호스트의 동등 도구로 실제 페이지를 조작하고 기대 결과를 관찰한다. 지속 회귀 테스트 파일/runner도 별도로 남긴다. 구조 HTML 생성·API 테스트·문서 설명만으로 브라우저 완료가 되지 않는다. [브라우저 상세](../integrations/playwright.md)

**DB:** DB 단위에는 `database: required`를 사용한다. 실제 catalog/제한 조회를 설계 근거로, 실제 재조회를 저장 검증 근거로 남긴다. 기존 profile·역할·정량 계획·행 수/시간 한도·fixture 정리 계약을 유지한다. 특정 외부 DB MCP 제품이 필수라는 의미는 아니며 기존 내부 SQL Server adapter도 사용할 수 있다. 미지원 쓰기를 일반 SQL MCP로 우회하지 않는다. [DB 상세](../integrations/database.md), [2.1 지원 범위](v2.1-operations.md)

## 구조화 산출물

### SystemDesign.tool_plan

다음 네 capability를 **각각 한 번씩**, 총 네 행으로 작성한다.

| 필드 | 의미 |
|---|---|
| capability | ui_design / library_docs / browser / database |
| mode | required / preferred / local_only / not_applicable. preferred·local_only는 UI 전용 |
| reason | 적용/미적용 이유, UI 대체 허용 범위 또는 실제 사용자 선택에 대한 설명 |
| unit_ids | 적용 단위 ID. 적용하면 알려진 단위가 한 개 이상, 미적용이면 빈 배열 |

UI 적용 단위 전체를 browser required의 unit_ids에도 포함한다. Gate A에서 이 표와 대안의 제품 영향을 실제 사용자에게 제시한다. Gate A 승인 전 상세 UI 생성을 완료할 의무는 없지만 적용되는 버전 의존 기술 선택의 문서 근거는 있어야 한다.

### SystemDesign / UnitSpec.tool_observations

공통 필드는 `capability`, `provider`, `tool`, `status`, `observed_at`, `target`, `summary`, `source_refs`, `result`다. `status`는 success/fallback/blocked이며 `observed_at`에는 시간대가 포함된 ISO 시각을 쓴다. blocked/fallback은 실제 `failure: {code, tool, detail}`가 필요하다. blocked의 result는 빈 객체이며 필수 결과를 충족하지 않는다.

source_refs에는 비밀 없는 HTTP(S) URL 또는 실제 `artifact:<artifact_id>/<revision_id>/<sha256>`를 쓴다. 없는 call ID·remote revision·artifact hash를 만들지 않는다. artifact 참조는 같은 run의 실제 현재 유효한 ref여야 하며 해당 StageRun/input_refs에도 포함한다. URL은 출처 연결이며 공급자 호출 자체의 인증이 아니다. 내부 source/대상 경로·인증 값·업무 원문을 외부 문서 질의에 전송하지 않는다.

| 관찰 | provider / result의 필수 내용 |
|---|---|
| Context7 문서 | context7 / library, version, sources(url/title), version_checked, library_id. 공식 원문·로컬 타입 대조 범위도 기록 |
| OpenAI 문서 | openai-docs / 문서 공통 필드, scope=openai, scope_reason, 공식 OpenAI 출처 |
| 공식 문서 대체 | official-docs / 문서 공통 필드와 local_type_check, 우선 도구의 실제 차단. OpenAI 범위는 scope/reason과 공식 OpenAI 출처 |
| Figma native | figma / file_key, node_ids, structure_checked=true, screenshot_checked=true |
| 로컬 UI | local-design / report_markdown, layout_content. local_only는 실제 user_choice, preferred 대체는 Figma failure |
| DB | 실제 공급자 / engine, target_ref, connection_mode=live, observation_kind=catalog 또는 readback, read_only=true, rows_observed, objects, checks |
| 브라우저 | 실제 공급자 / url, engine, browser_session, connection_mode=live, interaction_count, checks |

DB/브라우저의 checks는 실제 관찰한 name·expected·observed·passed를 담는다. 성공 증거에는 passed=true인 검증 결과가 있어야 한다. 실패를 통과값으로 바꾸지 말고 실제 failed/blocked 검증 시도를 보존한다. 정확한 result 필드·지원 failure code는 release schema를 읽는다.

### TestPlan.tool_checks와 실행 증거

browser/database 필수 단위는 `tool_checks: [{capability, check_id, evidence_id}]`를 작성한다. 연결된 check는 required이며 project-runner의 required JSON evidence 항목을 참조해야 한다. 내용과 경로·크기 한도는 기존 runner schema를 따른다. 라이브러리 문서와 UI 디자인은 설계 관찰이며 이 배열의 capability로 넣지 않는다.

JSON attachment는 다음 envelope를 사용한다. 이 표는 형식 설명이며 실행 결과가 아니다.

| 필드 | 실제 실행에서 가져올 값 |
|---|---|
| tool_policy_version | "1" |
| capability | browser 또는 database |
| build_id | 실행기에 의해 주입된 HARNESS_BUILD_ID |
| run_id | 실행기에 의해 주입된 HARNESS_RUN_ID |
| observation | 위 공통 관찰 schema의 실제 결과 |

MCP로 관찰한 경우 실제 응답을 읽은 후 준비한 증거 수집 경로로 전달한다. JSON 형식을 맞추기 위해 미실행 결과를 창작하지 않는다. 이전 build/run의 파일을 새 결과로 복사하지 않는다. DB 완료 근거는 readback이며 설계 때의 catalog 조회만으로 완료할 수 없다. DB 적용 단위는 Gate B의 environment-contract 또는 db-work-plan에 비어 있지 않은 target_ref를 명시하고, DB 관찰·검증 증거의 대상 전체가 그 승인 대상 전체와 일치해야 한다. 완료 증거의 source_refs 중 artifact 참조도 현재 승인 TestPlan의 input_refs 또는 승인 bundle에 속한 실제 유효한 ref여야 하며 가짜 참조·과거 참조를 새 근거로 사용하지 않는다. 브라우저는 실제 과업 상호작용과 기대값 확인이 필요하다. 회귀 runner의 case 결과는 별도로 통과해야 한다.

자동 첨부는 현재 제한된 text/JSON이다. screenshot/trace를 관찰에 사용할 수 있지만 PNG/ZIP이 자동 보존된다고 표시하지 않는다. 자세한 표준 템플릿은 [tool-plan](../templates/tool-plan.md), [tool-evidence](../templates/tool-evidence.md), [test-plan](../templates/test-plan.md)을 사용한다.

## Gate와 실패 판정

| 시점 | 검사하는 내용 | 완료로 처리할 수 없는 예 |
|---|---|---|
| Gate A | 네 capability의 계획·단위 연결, 적용되는 library_docs 근거 | 빈 계획, 알 수 없는 단위, 문서 조회 없이 버전 선택 완료 |
| Gate B | 해당 단위의 UI/문서/DB 설계 관찰, browser/DB의 실행 가능한 tool_checks 연결 | native 필수인데 로컬 이미지뿐, UI에 browser 계획 없음, DB 관찰을 mock으로 대체 |
| 실제 검증·완료 | 현재 build/run의 필수 JSON 첨부·관찰과 기존 required case/환경/소스/DB currentness | evidence 누락·과거 build 사본·skipped·catalog만으로 저장 성공 주장 |

권한·계정·쿼터·도구 부재는 제품 결함과 구분해 기록한다. required가 막히면 해당 항목을 waiting_tool/blocked로 남기고 독립 작업은 계속한다. 편의상 not_applicable로 바꾸지 않는다. 허용 대안이나 범위를 바꾸려면 해당 설계를 새 revision으로 보여주며 예전 승인을 새 조건에 붙이지 않는다.

## 초기 설정과 팀 배포

[START-HERE](../START-HERE.md)가 설치·진단 진입점이다. 공통 설치기는 Team Harness·12개 Skill을 개인 영역에 배치한다. 외부 공급자 계정·파일 권한·제품 DB 연결은 별도다. 선택한 호스트마다 설정 존재, 현재 세션 도구 노출, 인증, 허용 대상 읽기, 허용 대상 쓰기를 분리해 보고한다. Codex에서 연결됐다는 이유로 Claude Code에도 연결됐다고 표시하지 않는다.

기존 플러그인/MCP를 우선 사용하고 중복 설치·자동 계정 변경을 하지 않는다. 실제 계정 로그인/키 입력은 사용자 로컬 공급자 절차로 남긴다. 초기 설치만으로 Figma 임의 파일 생성이나 업무 DB 조회를 시작하지 않는다. 공개 문서의 작은 읽기 진단은 제품 시험과 구분한다. [호스트별 준비표](../integrations/connection-guide.md)

공통 Git 업데이트와 개인 release 설치는 별도다. 팀원은 새 원본을 받은 뒤 plan→install→실제 호스트 확인을 수행한다. 개인 .env·도구 보고서·제품 산출물은 공통 Git에 넣지 않는다. 이전 run은 기존 release/정책으로 재개한다.

## 범용 요청 예시

```text
development-workflow로 내가 지정한 프로젝트에 문서 관리 화면과 저장 API를 개발해줘.
먼저 기존 소스·DB·버전·사용 가능한 MCP를 조사해줘.
UI는 Figma를 우선 사용하고, 차단 시 로컬 배치안으로 대체할 조건은 Gate A에서 보여줘.
버전 의존 기술 결정은 Context7, OpenAI 관련 결정은 OpenAI Docs 근거를 사용해줘.
화면·백엔드·DB·검사의 정확한 변경 범위를 Gate B에서 보여주고 실제 승인 후 구현해줘.
실제 브라우저 과업 관찰, 저장된 회귀 테스트, DB 재조회 결과까지 검증해줘.
계정이나 대상 DB가 미정이면 필요한 항목만 질문하고 임의 연결을 가져오지 마.
```

이 요청은 예시이며 특정 프레임워크·DB 엔진·파일명·계정·Figma 대상·실제 승인을 정의하지 않는다. AI는 실제 프로젝트 조사와 사용자의 답변으로 상세화한다.

## 증거가 보장하는 범위

Harness는 계획과 제출 관찰의 구조, pin/승인 연결, 실제 runner가 수집한 JSON bytes와 build/run 연결을 검사한다. 공급자의 원격 호출 자체나 사용자 신원·현재 Figma 상태를 독립 인증하지 않는다. MCP 응답과 stdout/attachment 기록은 협조적으로 제출한 근거이므로 AI가 실제 호출을 읽고 사실만 작성해야 한다. 자유로운 셸/외부 도구 전체를 가로채는 보안 경계도 아니다.

도구가 정책대로 쓰였는지 제품적으로 평가하는 것은 사용자 검토와 실제 결과 확인이 함께 필요하다. 요구를 잘못 분류해 모두 미적용으로 넣거나 거짓 관찰을 쓰면 안 된다. 소스 snapshot은 DB·Figma·계정 상태의 백업/복원이 아니다.
