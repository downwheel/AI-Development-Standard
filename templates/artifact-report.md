# 개발 산출물 보고서 양식

이 파일은 작성 지침이다. 사용 시 아래 안내 문장을 실제 근거와 결과로 채운다. canonical 본문에는 자기 manifest hash를 넣지 않는다. 조회 카드가 발행 후 ref와 현재 상태를 표시한다.

## 목적과 이번 결과

사용자 목적, 이번 단계와 범위, 실제로 작성/조사/실행한 결과를 설명한다.

## 기준 자료

입력 artifact_id/revision_id/sha256 pins, 관련 요구/단위 ID, source snapshot 또는 관찰 범위·한계, 외부 근거의 관찰 시각을 기록한다.

## 상세 내용

해당 단계의 사실·요구·구조·계약·검사 내용을 실제 사례와 실패/복구 경로를 포함해 작성한다. 사실·추론·가정을 구분한다.

## 변경과 영향

이전 revision 대비 변경·유지·제외, 영향을 받는 후속 계약/승인/검사를 설명한다. 없는 이전판을 만들지 않는다.

## 검토 및 남은 사항

해결된 질문과 실제 답변 출처, 미확인·실패·차단, 다음 결정의 이유를 기록한다. 미실행 검사를 통과라고 쓰지 않는다.

## 실제 자료와 다음 단계

MD/JSON·native refs·필요 증거와 다음 Skill의 정확한 입력을 연결한다. 현재 승인·적용·검사 상태는 조회 projection과 구분한다.

환경/DB가 있는 단위는 안전한 profile/역할별 probe refs·정량 DB 계획과 scope refs를 연결한다. 개인 `.env`, 연결 문자열, secret-state, 원문 인증값은 이 양식에 넣지 않는다. 완료 보고는 next_actions/evaluate_completion의 실제 현재 판정과 구분하여 해당 단계의 산출물 작성 결과를 설명한다.
