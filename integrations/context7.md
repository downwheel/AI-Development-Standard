# Context7 MCP Server — Upstash

확인일: 2026-09-21. Context7 공식 저장소는 MCP 문서 조회와 별도의 CLI+Skills 방식을 안내한다. 이 표준은 버전 의존 결정에 현재 호스트의 Context7 MCP를 우선 사용한다. 계정·개인 설정은 초기 설정에서 준비도와 후속 작업을 구분한다. [공식 저장소·연결 안내](https://github.com/upstash/context7)

## 개인 연결

공식 문서의 현재 client 연결 절차를 확인한다. remote MCP 주소는 `https://mcp.context7.com/mcp`다. API key는 개인 secret 설정에 보관하고 공통 Git이나 입력 예제에 실제 값을 넣지 않는다. 공식 안내의 설정 도구는 로그인·키 생성·Skill 설치를 수행할 수 있으므로 읽기 조회와 구분해서 실행한다.

연결 후 작은 공식 라이브러리 질문으로 현재 노출된 기능을 확인한다. `resolve-library-id`는 library 식별, `query-docs`는 해당 ID의 문서 검색 역할이다. 정확한 실제 input schema를 확인해 호출한다.

## 사용 기준

다음에는 library_docs를 required로 계획한다: 시스템 설계의 새 프레임워크/라이브러리 선택, 단위 설계의 SDK/API·DB 드라이버·설정 계약, 구현 중 확인되지 않은 버전별 호출, 테스트 설계의 fixture·격리·대기 API. 외부 버전 계약이 없는 자체 로직은 구체적 이유로 not_applicable을 선택할 수 있다. OpenAI 제품/API에는 [OpenAI Docs](openai-docs.md)를 우선 사용한다.

프로젝트의 실제 package/lockfile 버전과 구체적인 질문을 먼저 정한다. 확인된 library ID는 재사용하고 필요한 부분만 검색한다. 출처·적용 버전·관찰 시각·결정에 사용한 근거를 개인 산출물에 남긴다.

결과가 존재하지 않는 API를 증명하는 것은 아니다. 공식 원문과 설치된 타입/SDK로 대조한다. 공식 저장소는 community 자료의 정확성·완전성 등을 보장하지 않는다고 밝힌다. 민감한 소스·DB 원문·자격증명을 문서 검색 질문에 전송하지 않는다.

신규 기술 선택 단계에 설치본이 없으면 공식 원문/배포 API·타입으로 확인한 범위와 로컬 타입 미확인을 구분하고 구현 전에 실제 설치본을 대조한다. Gate A 전에 이 검사만을 위해 제품 의존성을 설치하지 않는다.

문서 결과와 설치 버전이 맞는지, 공식 원문·설치된 타입/SDK의 어떤 부분이 설계 결정을 뒷받침하는지 기록한다. 시스템 설계에 기술 선택 근거를, 단위 설계에 구체적인 API/설정 결정을 tool_observations로 고정한다. 같은 버전·범위의 유효한 근거는 재사용하되 다른 버전 결과로 바꿔 끼우지 않는다.

계정/쿼터/네트워크 문제 또는 정확한 버전의 부재이면 실패 도구·원인과 공식 원문 대체를 함께 기록한다. 검색 없이 기억만으로 작성한 답을 Context7 조회로 표시하지 않는다. 검색 결과가 없다는 사실은 그 API가 존재하지 않는다는 증명이 아니다.
