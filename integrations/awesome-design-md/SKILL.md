# Awesome Design

1. 기존 프로젝트의 화면, 컴포넌트, 토큰을 먼저 조사한다.
2. references/INDEX.md에서 필요한 참조를 선택하고 해당 DESIGN.md만 읽는다. 자료는 특정 시점의 디자인 분석이며 현재 사이트와 같다고 단정하지 않는다.
3. 타이포그래피, 간격, 색상, 정보 계층, 상태와 반응형 동작 중 제품에 적합한 규칙만 적용하고 채택 이유를 짧게 설명한다.
4. 기존 제품 패턴과 충돌하는 브랜드 스타일은 도입하지 않는다. 타사 로고·문구를 사용자 제품에 그대로 복제하지 않는다.
5. 팀 설계 절차에 따라 Figma 또는 편집 가능한 로컬 시안으로 제시하고 승인 후 구현한다. 브라우저에서 실제 변경 화면과 비교한다.
